# Fountain Video — full software laboratory (no HDMI)

**Status:** Implemented, tested and running on the Ubuntu Mac mini on 24 October 2026.

## Decision and live service

Application-level video development must remain executable with **all physical cameras, HDMI cables, capture cards, Syphon bridges, proprietary drivers and firmware absent**. Hardware acceptance is a separate optional adapter process. The Nikon D5200 is switched off and need not be touched.

**Live browser laboratory (private network):** http://192.168.8.50:8272/lab

This service runs on Ubuntu host 'benedikt-Macmini', independent of the existing small virtual video demo on port 8172. The service is reachable from the modern Mac on the same LAN. It is not a publicly hosted website.

From any Python 3.10+ source checkout, standard library only:

    python3 -m unittest discover -s simulator/tests -v
    python3 -m simulator.lab_server --host 127.0.0.1 --port 8272

Visit http://127.0.0.1:8272/lab. By default the new service boots directly into a working two-device software loopback, already containing two transmitted and received frames, without needing a camera.

## Video instrument architecture

    Virtual camera (power, Live View, signal mode and pixel pattern)
                         |
                   simulated cable
                         |
                   Virtual receiver  <---- virtual signal ---- Virtual transmitter
                   2vuy + PCM                               scheduled 2vuy + PCM
                   capture frames                            playback frames
                         |
              software inspection and archive
                         |
          browser previews / HTTP data / Reframe / Teatro adapter

The virtual receiver and transmitter are **independently modeled half-duplex** devices. They can operate simultaneously only because they are **two separate instances**. The simulator rejects a same-device capture+playback conflict using the empirically observed vendor code 0x80000009. An input frame is an actual copy of the transmitter's generated bytes and audio, preserving timestamp and checksums, not an independently rendered coincidentally matching checkerboard.

No DeckLinkAPI import, kernel module, Syphon, Nikon, PCI mapping or physical HDMI input/output occurs.

## Implemented feature contract

| Function | Working software behavior |
| --- | --- |
| Historical format inventory | All 16 named modes, with exact rational frame rates |
| Video capture | Generated full-size packed 8-bit YUV422 (2vuy), frame CRC, geometry and timestamp |
| Video playback | Separate transmitter, scheduled output frames, auto-fill and queue underrun |
| Video patterns | Color bars, moving shape and checkerboard |
| Two-device loopback | Exact YUV and PCM byte equality, preserved presentation timestamps |
| Virtual camera | Power, Live View, source format, connector, simulated cable |
| Signal state | Connection, wrong mode, software protection/block, periodic drops |
| Mode detection | Fixed, first-change-only or continuous auto-detect, explicit format-change event |
| Video timing | Fraction-based master clock, monotonic across format changes, dropouts and underruns |
| Stereo audio | Signed little-endian PCM16, 48kHz two channels, deterministic tone/mute |
| Video/audio synchronization | Rational PTS, exact audio sample indices through 29.97/59.94 modes |
| Connector modeling | HDMI, component and SD-only composite/S-Video selection |
| Archive | Last six full-resolution input video buffers, corresponding PCM and JSON manifest in a deterministic ZIP |
| Inspection | Two browser monitors, mode/CRC, signal graph, dropped-frame counts, events and media metadata |
| API | JSON control; full generated YUV, PCM and PNG frame readout; ZIP download |

**Not emulated:** actual HDMI electrical signaling, proprietary firmware/DMA/PCI interrupts, decrypting HDCP, analog electrical conversion, actual interlaced field generation, real Syphon/NDI GPU publishing, real microphone input. Interlaced formats are represented in mode names/timing but are not falsely advertised as field-accurate hardware emulation.

## Browser / HTTP endpoints

The new browser lives at /lab. Read-only JSON: /api/lab/state and /api/lab/capabilities. JSON mutation routes:

- POST /api/lab/configure — select camera, camera-off, disconnected, mismatched, protected, dropped-frames, two-device loopback or playback-only scenario; choose mode, connector, pattern and detection policy.
- POST /api/lab/step — advance one to thirty logical ticks.
- POST /api/lab/source — change virtual camera power, Live View, cable, source format, mute or output queue behavior.
- POST /api/lab/queue — schedule one to thirty generated output frames.
- POST /api/lab/conflict — verify half-duplex refusal.
- POST /api/lab/stop — release both software instruments.

Media endpoints: /api/lab/input.png, /api/lab/output.png; /api/lab/input.2vuy, /api/lab/output.2vuy; /api/lab/input.pcm, /api/lab/output.pcm; /api/lab/archive.zip.

Every successful response includes X-Fountain-Simulation: true. The raw archive includes a manifest with generated-media provenance and exact frame/audio information. It is a **synthetic interchange/test archive**, not a consumer movie (.mov). It never contains photographs or audio from the Nikon or physical capture card.

Example source-owned software loopback:

    curl -H 'Content-Type: application/json' \
      -d '{"scenario":"loopback","mode":"720p50","pattern":"moving"}' \
      http://127.0.0.1:8272/api/lab/configure

    curl -H 'Content-Type: application/json' \
      -d '{"count":10}' http://127.0.0.1:8272/api/lab/step

    curl -o fountain-SYNTHETIC-frames.zip \
      http://127.0.0.1:8272/api/lab/archive.zip

## Execution / safety

The service listens on 127.0.0.1 by default. A trusted private-LAN bind requires an explicit --host argument; there is no authentication, so **do not publish this server to the Internet** or give it access to privileged real hardware. Mutations are JSON only with an 8192-byte request cap and forbidden cross-site Origin. No endpoint runs shell commands or touches device resources.

Existing minimal simulator on the same host port 8172 remains intact. The software lab is a separate process on port 8272.

## Witnessed acceptance

Ubuntu Python 3.12.3: **70 tests passed** for full-size video, sample-accurate audio, two-device link, scheduling, no-source, protected input, hot-swap continuity, half-duplex, media archive and live HTTP API. Node JavaScript syntax check passed.

The default software loopback served from 192.168.8.50:8272 was verified locally and from the modern Mac: input and output both delivered two frames with identical YUV/audio/PTS and physical_device_access=false. Both synthetic PNG endpoints returned valid images. The browser laboratory was visually checked in headless Chrome with two working preview monitors and matched CRCs.

**Physical capture was not claimed or attempted.** The Nikon was OFF, and the real Intensity Extreme/Sierra driver was not used in this software test.
