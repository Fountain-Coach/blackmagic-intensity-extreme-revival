# Browser Scratch and HDMI stream-adapter acceptance — 2026-10-24

## Scope

The source-neutral **native Sierra app → private-LAN JPEG receiver → browser scratching** path. The actual Nikon D5200 stayed OFF, so this report does not accept physical HDMI capture or output.

## Independently witnessed machines

- Sierra 10.12.6, original Intel Mac mini Uwes-Mac-mini, native Fountain Video.app running in the bene user session from /Users/bene/Applications/Fountain Video.app.
- Ubuntu Mac mini at 192.168.8.50, Python standard-library authenticated scratch server listening on TCP port 8273.
- Modern Mac, Chrome headless, Node 23 and macOS Python 3.14 for interactive and regression acceptance.

**Browser entry point:** http://192.168.8.50:8273/scratch (private WLAN only).

## Native Sierra video sender

The Sierra native app successfully built with Xcode 9.2 and now includes FCScratchPublisher, receiving the same 8-bit YUV-to-RGBA AppKit video preview from generated frames and from any future DeckLink vendor frame callback.

    stage=scratch_jpeg result=pass source=synthetic width=640 height=360 jpeg_bytes=8723 network_access=0

The app was deployed/reopened; the real sender uploaded JPEGs to Ubuntu with a secret authenticated POST, video PTS, stream-session UUID, real frame dimensions and source provenance. The source is explicitly tagged SYNTHETIC. The test pattern has a visibly moving square and binary frame signature, allowing visual verification of reverse and forward travel.

The receiver reported source_online=true, 144 retained frames, valid monotonic presentation times across current media session, bounded oldest-frame eviction, and an explicit new epoch from the native app restart. The last independent acceptance snapshot found 144 frames, 35.6 seconds of timestamp history, 485 evictions, stream_epoch=1 and hardware_hdmi_capture_accepted=false. These counts are momentary and depend on browser refresh time.

The source code now permits only **one outstanding upload** from the Sierra sender; the Python ring discards late out-of-order packets without destroying valid history. A new source/session or significant clock reset starts a new epoch.

## Privacy/safety boundary

- Sender/receiver are on the private 192.168.8.0/24 LAN. The ingest token was generated by the machine, stored only in private host files/preferences, and never committed.
- **No TLS and no viewer authentication**: this is a trusted-LAN prototype only. Do not forward the port to the Internet or stream private footage over untrusted Wi-Fi until viewer auth/TLS are available.
- Receiver retains frames only in bounded RAM; no video file is recorded automatically.
- Original Blackmagic 10.4 kernel drivers remain loaded. Independent replacement KEXT is unloaded. No firmware, PCI, HDCP, monitor-mode or HDMI source changes were made.
- The physical Nikon was OFF. **No HDMI input frame, HDMI output signal or real-device repair was demonstrated.**
- Currently the browser preview is bounded to 640×360 JPEG at up to roughly 5.8 generated frames/s, not full-frame-rate low-latency HDMI streaming. Audio is not included in the scratch transport.
